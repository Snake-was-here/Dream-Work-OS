# Source coverage

These are source families and starting points, not claims of current vacancies. Inspect each actual opportunity before recording it.

| Source family | Starting point / approach | Contact rule |
|---|---|---|
| Startup jobs | YC Work at a Startup, Wellfound, company careers | Official application or requested route |
| Hacker News | Current “Who is hiring?” and “Freelancer? Seeking freelancer?” threads on news.ycombinator.com | Original poster's requested email/application |
| Founder communities | Public founder/startup posts and communities | Only replies/DMs permitted by poster and community |
| Reddit | Relevant for-hire, startup, automation and product communities | Check current community rules and the original demand post |
| Public LinkedIn jobs/posts | Public listing and official company vacancy | Explicit application route; do not invent email |
| Freelance marketplaces | Accessible Upwork and comparable project listings | On-platform proposals; honor platform rules |
| AI/automation communities | Public requests for implementation or workflow help | Requested professional route |
| GitHub | Issues/discussions explicitly requesting paid help or hiring | Do not turn ordinary bug reports into unsolicited sales leads |
| Agencies | Public subcontractor/vendor requests or contract listings | Stated work inquiry route |
| Remote job boards | Remote OK, We Work Remotely, Remotive and original company listing | Verify original vacancy and location restrictions |
| Company careers | Canonical career page | Official application, latest active listing |

Do not assume access to a logged-in platform. State access limits, use a legitimate public alternative when possible, and leave activity uncertain when original verification is impossible. Add useful new sources with date, access constraints, observed quality and rationale; retire noisy sources based on outcomes rather than one empty search.
